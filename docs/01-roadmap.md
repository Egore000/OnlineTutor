# 1. Назначение документа

Roadmap определяет последовательность разработки проекта.

Документ является обязательным для исполнения.

После утверждения Sprint не меняется.

Изменения допускаются только если:

- обнаружена критическая ошибка проектирования;
- изменилась бизнес-требование;
- завершение спринта невозможно без корректировки.

---

# 2. Правила разработки

## MVP First

Каждый спринт должен завершаться рабочим функционалом.

После каждого Sprint проект должен запускаться.

---

## Никакого Overengineering

Запрещается добавлять функциональность "на будущее".

Если функция не используется в ближайших двух спринтах — она не разрабатывается.

---

## Один спринт — одна цель

Каждый Sprint решает одну крупную задачу.

---

## Минимум рефакторинга

После завершения Sprint архитектура считается стабильной.

---

# 3. Definition of Done

Спринт считается завершённым если:

- функциональность полностью реализована;
- написаны тесты;
- код проходит Ruff;
- код проходит mypy;
- миграции созданы;
- документация обновлена;
- OpenAPI актуален;
- отсутствуют TODO.

# 17. Приоритеты

Приоритет разработки определяется следующим образом.

| Приоритет | Описание |
|-----------|----------|
| Critical | Без функции MVP невозможен |
| High | Значительно повышает ценность MVP |
| Medium | Улучшает пользовательский опыт |
| Low | Может быть реализовано после MVP |

---

# 18. MVP Scope

В MVP входят следующие модули.

✅ Авторизация

✅ Ученики

✅ Предметы

✅ Материалы

✅ Расписание

✅ Домашние задания

✅ Проверка домашних заданий

✅ AI-помощник

✅ Прогресс

---

Не входят:

❌ Родители

❌ Организации

❌ Платежи

❌ CRM

❌ Онлайн-школа

❌ Мобильное приложение

---

# 19. Критерии успешного MVP

MVP считается завершённым, если преподаватель способен:

- зарегистрироваться;
- добавить ученика;
- создать предмет;
- загрузить материалы;
- назначить занятие;
- выдать домашнее задание;
- получить выполненную работу;
- проверить работу самостоятельно или с помощью ИИ;
- просмотреть историю обучения ученика.

После достижения этих критериев проект переходит в стадию эксплуатации и дальнейшего развития.

# 20. План работы
